## Context

支持站是五语言静态 HTML 网站，各语言目录提供主页、支持页和隐私页，共享 `style.css` 与 `language-switcher.js`。首页 `.page-actions` 已使用支持换行的 flex 布局，依次展示 App Store 徽章、支持按钮及隐私说明链接。既有语言选单通过页面内链接切换同名页面。

本变更只在支持站仓库规划及实施。五语言介绍页需要统一内容、地址、元信息和导航，避免翻译或链接复制造成不一致。

## Goals / Non-Goals

**Goals：**

- 在隐私说明链接之后提供同语言的 frp 介绍入口，桌面在其右边，窄屏自然换行。
- 用易懂的内容解释 frp、`frpc`、`frps` 和 FerryPorts 的关系，提供官方项目入口。
- 新页覆盖英语、简体中文、繁体中文、日语和韩语，保留同页语言切换及可访问性。

**Non-Goals：**

- 不调整应用源代码、应用内导航或父仓库 submodule 指针。
- 不扩展为服务端部署教程，不新增应用支持能力或永久后台在线等承诺。
- 本次规划不执行页面实施、Git 提交、推送或 GitHub Pages 发布。

## Decisions

### 页面与首页入口

统一使用 `<lang>/frp.html`，新增 `en/frp.html`、`zh/frp.html`、`zh-Hant/frp.html`、`ja/frp.html`、`ko/frp.html`。短文件名与既有 `support.html`、`privacy.html` 一致；不采用首页弹层，因为独立页面方便直接访问及切换语言。

在五语言 `index.html` 的 `.page-actions` 中，将普通文字链接直接追加在隐私说明链接之后。简体中文固定为「什么是 frp？」，其余语言采用自然的等义问句，`frp` 保持小写。复用当前 flex 换行，只有实际验证发现裁切或间距问题时才调整 `style.css`，避免共享样式影响原有页面。

### 内容结构与事实来源

首页在应用介绍后补充一段五语言用途摘要，概括在家访问公司电脑上的 kimi code、deepseek harness 等 Web 服务、远程使用电脑终端或桌面、在外读取与备份 NAS 文件。按审阅反馈移除首页的后台运行限制句，将服务器配置前提合并到用途段落；详细应用限制继续在介绍页和支持页提供。

介绍页依次包含：frp 的定义及用途、`frpc` 与 `frps` 的工作关系、典型场景、FerryPorts 的角色、官方 GitHub 链接及同语言支持入口。采用自写的简明介绍，避免复制上游长篇 README 或嵌入远程页面。

内容以官方项目 `https://github.com/fatedier/frp` 为事实来源；已于 2026 年 10 月 10 日核对。介绍内网服务访问、反向代理及 TCP、UDP、HTTP、HTTPS 等 frp 概念时，明确这些是上游项目能力，不推导 FerryPorts 支持上游全部功能。说明 FerryPorts 是 iOS 上的 frp 客户端，用户需自行准备有权访问的 frps 服务器及配置，后台运行受 iOS、网络状态和权限限制。

先确定英语内容基线，再完成其他四种语言，保证章节及含义一致。服务器地址、配置标识与官方 URL 保持原值，不固定上游版本号、星标数或其他易过时数据。

### 导航、语言与检索

新页复用既有主导航、页脚、跳过导航及正文结构，提供同语言首页与支持入口。语言选单保持原有交互及无脚本回退，四个其他语言链接均指向对应的 `frp.html`；当前语言显示不可激活的文本。每页配置本语言 `lang`、标题、描述、canonical、Open Graph 元信息、五语言 alternate 及英语 `frp.html` 的 `x-default`。

在 `sitemap.xml` 加入五个新页的绝对地址，并更新本站 `openspec/config.yaml` 的页面类型清单。既有支持页和隐私页地址不迁移；本次不需要修改共享选单脚本。

### 外部链接

五语言介绍页均提供可辨识的官方 GitHub 项目链接，精确指向 `https://github.com/fatedier/frp`，沿用普通链接的当前页面导航行为。仅用户激活时前往 GitHub，不嵌入 GitHub 图标、徽章、API 数据或其他第三方资源。

## Risks / Trade-offs

- 五语言静态页面会重复结构 → 统一章节清单，实施时检查五页元信息、同名语言链接及内容等义。
- 新增链接可能令操作行提前换行 → 保持 DOM 顺序，在宽屏、320 CSS 像素及 200％ 缩放下验证；不强制所有入口在同一行。
- 上游能力可能被误认为应用承诺 → 明确区分 frp 原理与 FerryPorts 的实际用途，以现有支持页为应用事实边界。
- CSS 调整会影响现有页面 → 优先复用；如确需修改，回归原有徽章、支持按钮和语言选单的布局及明暗主题。

## Migration Plan

实施后先本地检查五语言首页入口、新页和站点地图，再验证浏览器布局、键盘及禁用 JavaScript 的行为。发布时，新页与首页入口作为同一次站点变更交付；提交、推送、发布需在获得相应授权后执行。若需回退，撤回本次新增入口、新页及地图条目，保留原有地址。

## Open Questions

无阻塞项。其余四种语言的具体入口问句及正文将在实施时按当前语言自然表达确定，并进行等义审校。
